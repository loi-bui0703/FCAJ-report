Worklog Tuần 5

Mục tiêu tuần 5:

  • Tôi hoàn thành lộ trình container của Cloud Journey từ đóng gói ứng dụng cục bộ đến managed orchestration và automated delivery. Nội dung bao gồm image construction, Amazon ECR, Amazon ECS với AWS Fargate, Amazon EKS, load balancing, scaling, deployment strategy và CI/CD control.
  • Hoàn thành từng nội dung bằng nghiên cứu có nguồn, thực hành có kiểm soát, xác minh kết quả và dọn dẹp tài nguyên khi cần.

Các công việc cần triển khai trong tuần này:

ThứCông việcNgày bắt đầuNgày hoàn thànhNguồn tài liệu
2Thiết kế container image và Amazon ECR
Kiến thức:
• Tìm hiểu container, image, registry, layer, build context, Dockerfile instruction, environment configuration, port exposure và health check.
• Nghiên cứu image-tagging strategy, immutable artifact, Docker Compose cho local dependency và sự khác nhau giữa build-time với runtime configuration.
• Tìm hiểu ECR repository, authentication, lifecycle policy, encryption và image vulnerability scanning.
Thực hành:
• Containerize ứng dụng mẫu bằng multi-stage Dockerfile và cấu hình runtime không dùng root.
• Build, chạy image local, dùng Docker Compose cho thành phần phụ thuộc và test cấu hình qua environment variable.
• Tạo ECR repository, xác thực Docker client, tag/push image và khởi chạy image scanning.
Xác minh:
• Kiểm tra container startup, health status, application response, log, image size và khả năng tái sử dụng layer.
• Rà soát scan result và ghi mức ưu tiên remediation cho package vulnerability được phát hiện.
• Ghi source commit, image tag và image digest để duy trì traceability của artifact.		13/07/202613/07/2026Lộ trình Container Services

Amazon ECR image scanning
3Amazon ECS service, discovery và load balancing
Kiến thức:
• Tìm hiểu ECS cluster, task definition, task, service, capacity option, container dependency, task role và execution role.
• Nghiên cứu Application Load Balancer listener, target group, health check, Cloud Map namespace, service discovery và security-group path.
• Xác định cách inject configuration/secret mà không nhúng credential trong image.
Thực hành:
• Tạo task definition cho frontend/backend với resource limit, port mapping, log, health check và trách nhiệm IAM tách biệt.
• Deploy ECS service, đăng ký discovery name trong Cloud Map và kết nối đường frontend qua Application Load Balancer.
• Cấu hình network/security group để chỉ mở service-to-service và load-balancer path cần thiết.
Xác minh:
• Xác nhận target health, task stability, DNS-based service discovery, frontend-to-backend communication và log delivery.
• Dừng một task và quan sát ECS tự khôi phục desired count.
• Lưu task-definition revision, service event, target-health evidence và request path cuối cùng.		14/07/202614/07/2026Workshop Amazon ECS
Amazon ECS best practices
4AWS Fargate, scaling và deployment strategy
Kiến thức:
• Tìm hiểu Fargate như serverless compute cho container, gồm task sizing, networking, ephemeral storage, logging và platform version.
• Nghiên cứu desired count, service auto scaling, target-tracking policy, rolling update, blue/green deployment, traffic shifting và rollback.
• So sánh deployment safety, temporary capacity, observability requirement và cost trade-off của từng rollout strategy.
Thực hành:
• Chạy ECS workload trên Fargate và điều chỉnh task CPU/memory cho mức tải mẫu.
• Cấu hình target-tracking scaling policy rồi tạo traffic có kiểm soát để theo dõi thay đổi task count.
• Chuẩn bị blue/green deployment với target group riêng và chuyển test traffic sang application revision mới.
Xác minh:
• Kiểm tra scale-out/scale-in event, running task count, target registration và availability trong khi test.
• Tạo health check thất bại có chủ đích và xác nhận traffic không được chuyển sang deployment không khỏe mạnh.
• Ghi rollback criteria, monitoring signal, capacity overhead và điều kiện chọn rolling hoặc blue/green.		15/07/202615/07/2026Monolith to Microservices with Fargate
AWS Fargate for Amazon ECS
5Vận hành Kubernetes workload trên Amazon EKS
Kiến thức:
• Tìm hiểu trách nhiệm EKS control plane, managed node, pod, deployment, service, namespace, ConfigMap, Secret, RBAC và add-on.
• Nghiên cứu Kubernetes networking, workload identity, request/limit, probe, rolling update và workload inspection.
• So sánh ECS service abstraction với Kubernetes deployment/service abstraction.
Thực hành:
• Chuẩn bị EKS learning environment và xác nhận quyền truy cập bằng Kubernetes command-line tooling.
• Deploy workload mẫu vào namespace riêng với deployment, service, configuration, resource request và health probe.
• Áp dụng namespaced RBAC rồi rà soát workload identity cùng add-on configuration.
Xác minh:
• Kiểm tra node, pod, event, log, rollout status, endpoint và khả năng truy cập service.
• Xóa một pod để xác nhận reconciliation, sau đó update image để quan sát controlled rollout.
• Ghi lại manifest, command, authorization check và troubleshooting sequence.		16/07/202616/07/2026Get started with Amazon EKS
Amazon EKS Best Practices Guide
6Automated delivery đến EKS và cleanup
Kiến thức:
• Tìm hiểu CodePipeline stage, source event, CodeBuild project, build specification, artifact, service role, approval gate và deployment evidence.
• Nghiên cứu authentication cùng Kubernetes authorization để CI/CD identity có thể cập nhật EKS workload.
• Tìm hiểu artifact promotion, immutable image reference, pipeline failure handling và rollback requirement.
Thực hành:
• Kết nối GitHub source với CodePipeline, build/push container image mới qua CodeBuild và cập nhật EKS workload.
• Giới hạn pipeline/build role cho đúng repository, logging, artifact, registry và cluster action cần thiết.
• Commit một thay đổi hiển thị rõ, sau đó theo dõi từ source revision qua build, image digest, deployment đến public response.
Xác minh:
• Xác nhận stage success, xem build log, kiểm tra deployed image digest và test ứng dụng đã cập nhật.
• Tạo controlled build failure và dùng log xác định failed stage mà không ảnh hưởng current deployment.
• Lưu bằng chứng rồi xóa EKS, ECS, load balancing, registry và pipeline lab resource theo cleanup inventory.		17/07/202617/07/2026CI/CD on EKS với CodePipeline và GitHub
AWS CodePipeline concepts

Kết quả đạt được tuần 5:

  • Kiến thức đạt được: Tôi hiểu toàn bộ container delivery chain từ source code và Docker layer đến immutable ECR image, ECS task hoặc Kubernetes pod, service discovery, load balancing, scaling và controlled deployment. Tôi phân biệt trách nhiệm ECS/EKS thay vì xem cả hai chỉ là công cụ chạy container.

  • Kỹ năng thực hành: Tôi đã build/scan image, deploy multi-service workload trên ECS, chạy Fargate task, kiểm thử scaling và blue/green, vận hành Kubernetes deployment trên EKS, đồng thời đưa application revision qua CodePipeline và CodeBuild.

  • Nhận thức về security, operations và cost: Giải pháp dùng non-root container, runtime role, restricted network path, health probe, log, immutable image identity, scoped pipeline permission, failure test và rollback criteria. Tôi theo dõi capacity overhead và xóa cluster, load balancer, pipeline có chi phí cao sau khi xác minh.

  • Sản phẩm đầu ra và bằng chứng: Các đầu ra gồm Dockerfile/Compose configuration, ECR scan record, ECS task/service definition, request-path diagram, scaling/deployment observation, Kubernetes manifest, RBAC note, pipeline configuration, build/deployment log, image-digest trace, functional test result và cleanup checklist.
